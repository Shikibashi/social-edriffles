OAuth is fixed and deployed to the existing `social.edriffles.us` deployment.

The error was caused by an older web bundle carrying a loopback origin into OAuth:

```text
http://127.0.0.1:19006
```

AT Protocol OAuth requires the production `client_id` to be a fully qualified HTTPS URL pointing to the public client metadata document. Its localhost exception is limited to a special `http://localhost` client ID, and IP addresses such as `127.0.0.1` are not valid client IDs. [AT Protocol OAuth specification](https://atproto.com/specs/oauth)

I changed the OAuth boundary so that:

- The hosted application detects `https://social.edriffles.us` at runtime.
- The runtime OAuth `client_id` is forced to:

```text
https://social.edriffles.us/oauth-client-metadata.json
```

- The runtime web callback is forced to:

```text
https://social.edriffles.us/oauth/callback
```

- A stale local build origin cannot silently become the production client ID.
- Local development origins remain configurable.
- Native callback behavior remains unchanged.
- The metadata document and runtime OAuth client continue to share the same origin-bound values.
