# WP-003 — Publish the community Space Lexicon

## Outcome

An external Space-aware client or OAuth provider can resolve `org.radlib.community` as a `type: "space"` declaration, learn its name/key/collection contract, and materialize only the declared community-post collection into a scoped `space:` grant.

## Evidence and assumptions

- The current URI type constant is `org.radlib.community`; no checked-in Space declaration was found.
- `org.radlib.private.post` is the current private community record collection. Standard `com.atproto.simplespace` owns membership/policy and `com.atproto.space.*` owns records/credentials.
- Existing alpha fixtures use `com.example.group` with a declared collection list and already test bare-grant materialization and undeclared-collection rejection.
- The chosen key type is `any` because the fork generates a base64url community space key; if the pinned Lexicon schema rejects this choice, stop and resolve the key contract before implementation.

## Scope

- Add `upstream/atproto-pds/lexicons/org/radlib/community.json` with `id: "org.radlib.community"` and `defs.main.type: "space"`.
- Declare a human-readable name (for consent text), `key: "any"`, and the minimal initial collection list containing `org.radlib.private.post`.
- Regenerate the PDS Lexicon source/barrels using the existing `pnpm ... codegen:lex` command; do not hand-edit generated files.
- Add a focused test using the existing Lexicon-authority test fixture that resolves this declaration, materializes its collection into a bare grant, and verifies an OAuth write rejects an undeclared collection.
- Document the authority-DID publishing/configuration requirement in the implementation handoff; do not mutate the live authority or deploy a Lexicon service here.
- Do not broaden the collection list for future notes, moderation, or notifications until each collection has an owner and authorization contract.

## Tests written first

Create `upstream/atproto-pds/packages/pds/tests/space/radlib-community-lexicon.test.ts` before implementation. It must assert:

1. the declaration has `type: "space"`, `key: "any"`, a bounded name, and exactly the intended initial collection set;
2. the Lexicon authority resolves `org.radlib.community`;
3. a bare OAuth space grant materializes `org.radlib.private.post` for the declared space;
4. an undeclared collection cannot be created through that grant;
5. an explicit authority/collection/action scope is accepted only for the matching community Space and collection.

Expected red result before implementation: the type cannot resolve and bare-grant collection materialization has no community declaration to consult.

## Implementation

1. Add the source Lexicon JSON with the smallest collection set.
2. Run the existing PDS Lexicon generator and inspect the generated diff; generated output must be limited to the new declaration/barrel exports.
3. Add the focused provider-resolution test using the existing `lexiconAuthority: true` network setup.
4. Keep `COMMUNITY_SPACE_TYPE` unchanged so existing URIs remain stable.
5. Verify the client’s current direct DPoP transport still compiles and passes; no OAuth/provider-selector change is included.

## Acceptance

- The new focused Lexicon test and existing `tests/space/auth.test.ts tests/space-scope.test.ts` cases pass.
- Lexicon code generation is reproducible and produces no unrelated changes.
- `python3 scripts/validate_contract.py` and `python3 scripts/check_upstream.py --fast` pass.
- The resulting implementation handoff names the authority DID/configuration needed for external resolution and states that deployment is still alpha/test-only.

## Risks and stop conditions

- Stop if `key: "any"` is not accepted by the pinned Lexicon schema or if generated output changes unrelated upstream surfaces.
- Stop if the authority cannot publish/resolve the declaration without a new external service or production mutation; mark external resolution `UNVERIFIED` rather than guessing.
- Do not add wildcard collection permissions as a shortcut.

## Handoff

Hand off the generated Lexicon diff, provider test output, exact declared collection list, and unresolved authority-publishing requirement to WP-004.
