# Identity Sovereignty UI v1

The Identity sovereignty screen distinguishes DID identity, verified handle, PDS hosting, AppView presentation, services, recovery, migration, and portable personalization. Advanced authority rows are generated from `AUTHORITY_MAP`; diagnostics redact tokens, passwords, secrets, refresh material, and private keys.

Migration capability is labeled Simulated where repository/blob transfer is not available upstream. Runtime states are never presented as live production capability. Service/provider changes remain explicit and separate from identity authority. Recovery and lockdown semantics are described as session revocation, write blocking, cache invalidation, remembered-service disabling, and fresh verification—not as network-wide guarantees.
