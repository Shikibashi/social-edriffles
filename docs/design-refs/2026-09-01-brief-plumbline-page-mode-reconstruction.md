# Brief: Plumbline Page Mode editorial reconstruction

## Status

Current, product-derived correction for the desktop Page Mode of Plumbline at
`https://plumblines.uk/`.

The product owner has rejected the previously rendered Plumbline shell as a
failed visual direction. It remains historical evidence, but it is not an
acceptable target for further incremental refinement.

## Product proposition

Plumbline is a user agent for the AT Protocol: a serious radical periodical
that became an interactive desktop information system. It should expose the
institutions acting through the network without turning ordinary reading into a
protocol debugger.

The Page Mode composition is:

```text
INDEX / NAVIGATOR | EDITORIAL DOCUMENT STREAM | MARGINAL INSPECTOR
```

The three areas are deliberately unequal. The document stream is the reading
surface and owns the visual weight. The index supports orientation. The margin
explains provenance, rules, and available control.

## Rejection record

The rejected render communicated an upstream social-application shell with an
ECW skin: a narrow central column, product identity confined to navigation,
`WORKSPACE` and `DOCUMENT STREAM` as primary labels, and a boxed inspector.

Do not repair that composition with more decorative tokens. Change the shared
desktop Page Mode boundary and move ordinary reading routes out of workbench
presentation.

## Required visual outcome

- A full-width masthead establishes PLUMBLINE before route chrome.
- The masthead has a full wordmark, restrained open-web descriptor, rules, and
  the quiet `ALIGN · INSPECT · UNDERSTAND` motto.
- The navigator reads like an index, with compact sections and plumb-line
  selection geometry.
- The stream reads like a named edition or section, not a dashboard workspace.
- Posts form a continuous document with vertical provenance geometry, readable
  measure, printer-like separators, integrated media, and compact actions.
- The inspector reads as marginal reference apparatus using typographic labels,
  definition-like details, and rules rather than card containers.
- The hierarchy must survive grayscale: type, rules, scale, alignment, spacing,
  and marker shape establish meaning before brass color does.

## Scope

This is a visual and information-architecture correction only.

- Preserve route ownership, provider composition, ranking, moderation, identity,
  migration, private association, OAuth, Spaces, posting, engagement, reply,
  quote, and chat behavior.
- Preserve browser-native links, focus treatment, semantic labels, state and
  recovery behavior, and existing mobile navigation.
- Keep workbench grammar for Services, Identity, Moderation and Reach,
  diagnostics, and advanced configuration.
- Do not introduce new remote assets, a new provider, an authorization scope,
  or a new protocol claim.

## Evidence mode

Product-derived. The canonical requirements are the product owner instruction,
`docs/design/PLUMBLINE_DESIGN.md`, and `DESIGN.md`. The current rendered
baseline is evidence of a rejected composition, not an alternate product
direction.
