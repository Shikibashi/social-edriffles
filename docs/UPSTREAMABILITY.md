# Upstreamability

Potentially upstream-generic: endpoint validation, secret-redacted diagnostics, accessibility and neutral provider-boundary tests, and deployment safety checks, subject to upstream API conventions. Project-specific or constitution-specific: Identity authority/cache semantics, Candidate/Attention sovereignty, Portable Personalization contracts, explicit provider fallback, and authority matrices. Root fixtures and release gates are not suitable upstream.

An upstream proposal must remove project-specific political framing, include focused tests, and preserve the frozen contract as an explicit acceptance criterion. No automatic pull requests are opened by the update checker.
