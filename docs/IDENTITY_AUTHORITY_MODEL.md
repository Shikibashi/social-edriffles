# Identity Authority Model

- **Identity-authoritative:** DID subject, signing-key succession, repository ownership, handle verification relationship.
- **Portable user data:** repository records/blobs where ATProto permits, association records, exported Portable Personalization, explicitly selected services.
- **Service-derived:** AppView indexes, moderation labels, ranking traces, provider health, reputation assessments.
- **Local client:** session presentation, cached resolution, device preferences, UI state.
- **Revocable delegation:** OAuth grants, service-auth tokens, app passwords, recovery-provider grants.

A handle may change without changing DID. A PDS may change without changing DID. An AppView may change without changing repository authority. No provider can mint interpersonal relationships or identity claims through attention APIs.
